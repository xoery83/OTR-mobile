# Root2 read-only verification and transfer protocol

1. Read this fixed package; verify source main and actual container/image/config/mount/bundle fingerprints. Verify actual DEV project, health, current schema ledger and affected Source fingerprints against evidence timestamps. Config/env secrets stay on the existing Host, never returned in a report.
2. Independently inspect current service, rollback existence, absent finite selectors, worker/timer status and `/proc/locks` holder without acquiring a lock. Reconcile Root1 versus Root2 hash canonicalization. Preserve unobserved facts as UNKNOWN; don't probe availability with business calls.
3. Return **ROOT2_READ_ONLY_VERIFIED** for this exact package/SHA/resources with your measured evidence. This is not Writer acceptance or deployment permission. Any unexplained drift or active protected operation stops transfer; Root1 remains Writer and freezes new writes while reconciling.
4. Root1 commits **ROOT1_HOSTED_WRITER_RELEASED** to WRITER_STATE after matched independent verification and sends the fixed release SHA. Release only the scoped DEV Host/Backend/runtime/approved-install execution domain; Root1 keeps Core/schema source/main. Root1 performs no further Hosted mutation. If acceptance fails, rollback ownership through a recorded reversion/MC confirmation before Root1 writes again; never silently resume.
5. Root2 explicitly returns **ROOT2_HOSTED_WRITER_ACCEPTED** for the same resource IDs, release SHA, authority limits and no-active-window facts. There is no transfer to the similarly named parent chat or another agent.
6. MC records the same resource as Root2's unique Hosted Writer, with release/acceptance event IDs; not just Source Integration status. MC ACK pending does not stop independent local work, but **does block Hosted writes until ownership is recorded**.
7. Root2 runs one **no-business-write** health/default-close readback after ownership registration; records actual service/config/selector/worker/scope outcomes. No deployment/restart/SQL/Provider test is required for this check. Only after all steps may Root2 process a legal READY packet within corresponding valid permissions.

Failure semantics: before formal release keep Root1; after conditional release Root1 stays quiescent and Root2 cannot mutate until acceptance/MC/readback complete. If a transition fails, restore the original recorded Writer through an explicit event, not two parallel Writers. Existing flock controls short mutations; this file documents responsibility and does not itself create/hold an OS lock.
