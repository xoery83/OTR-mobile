## APPROVED RISK AUTHORIZATION — v1.1.0

Owner-approved change: do not ask the user to click an extra operation approval for normal L1 or sensitive reversible L2 writes. Read the current object/permissions, build only requested changes, PREVIEW the exact concrete call, then APPLY that same original operation/idempotency key and previewDigest using current OAuth write authority. Explain important L2 side effects before execution; the explanation is not a server credential. Never silently add fields/targets or retry an UNKNOWN mutation.

Risk comes from the server's machine registry and actual typed request, not the model. Trip creation/name/dates/normal metadata, P1–P6 normal creation/update and ordinary Expense creation/update are L1. Single-item/Expense hide/delete/restore, Trip archive/unarchive, financial evidence/allocation and linked-data changes are L2. An Expense update that changes participants/splits/payer/settlement participation is L2. Whole Trip delete, journey-wide currency commit, or large aggregate destructive impact is L3 and still requires PREVIEW → TRUSTED CONFIRM → identical APPLY. External OTR confirmation is permitted only for L3 while a trusted in-chat channel remains unqualified. Missing L3 confirmation means stop, not fallback to scope/model approval.

Read the risk metadata from get_otr_capability_schema. The server may escalate for actual downstream impact. Do not split a batch or multi-step intent into individually lower-labelled calls to evade L3. Do not execute a multi-target destructive plan without its aggregate approval. Formal OAuth identity, Trip ACL, validators, CAS/Revision, original Operation/Receipt and UNKNOWN recovery remain unchanged. A CONFIRM plan step or userConfirmed boolean is never approval. Settlement/Personal Payment/Personal Review writes, member removal, ownership transfer and uploads remain out of scope.

Beta machine threshold:10 distinct destructive targets constitute aggregate L3. Declared concrete plans are assessed before execution; durable serialized account/resource admission across clients also blocks the10th distinct destructive target within15minutes. Failed/UNKNOWN reservations consume budget conservatively until expiry; no deletion/reset to force tests. This is a bounded anti-decomposition rule, not inferred natural-language intent. Existing single-target operations retain L2.
