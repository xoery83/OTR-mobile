## 1. 合同读取与Schema制品

本文件为唯一Server Capability Registry，AI文档通过Stable ID引用，不另写一份字段合同。`R_`、`S_`是文档Schema名称，不是新数据库或运行时Authority。JSON/TypeScript示例只定义数据形状。本轮不生成可执行服务代码。

既有Schema以本节Source Alias表中的**固定Main文件+export+完整文件SHA256**为规范性引用，包含Zod refinement、默认值及引用类型。Layer 1/2从同一Main SHA各自提取只读副本即可独立校验，无需等待另一Agent导出Schema。只读规范副本不属于双方可写实现文件。自定义refinement不能在导出JSON Schema时丢弃，必须保留语义断言ID。新Schema使用本文件完整类型定义。

冻结后交接包以 `otr.mcp-beta.contract/1.0.0` 标识，包含文档Registry、下述Source Alias/哈希、可提取JSON Registry与各Schema。Layer 1只补实现，Layer 2只写Guide和Plan，不修改这个冻结包。必需的合同修订集中提交Owner，附兼容性和新的版本，不能靠运行时自由字段协商。

## 2. 全局值、写入及恢复语义

- UUID为小写标准UUID。Revision为0..9007199254740991安全整数，Item已存在Revision>=1。新的操作ID用UUID，是既有Ledger localId/idempotency字符串合同的合法子集，保留历史非UUID字符串读取兼容。
- HTTP Account由正常认证Context取得，禁止body中自报actor/role/owner提升权限。Trip路径与command.tripId相等，跨Trip行为是两次分别授权的操作，不允许直接改Item.trip_id。用户明确“移到另一个Trip”只在有正式Move Port时可规划执行，本Beta不存在该Port，返回UNSUPPORTED_OPERATION，不通过删建冒充Move。
- 所有Mutation带既有Idempotency-Key和原operation/command identity。Core header `X-OTR-Core-Contract-Version: 2`，命令contractVersion/intentVersion均2，MANUAL admission的sourceIntentId/policyVersion均null。Beta只接正式用户授权结构化业务请求，不使用IMPORT/REVIEWED_SOURCE/AUTO_SOURCE或Source Proof创造权限。
- canonical request body与原ID绑定。重复同ID同intent返回原Receipt，不重复提交。相同ID不同intent为IDEMPOTENCY_CONFLICT。操作返回后重新读同ID和当前Revision，不能用LLM文本或HTTP200作为保存成功。
- 省略是保持原值。nullable字段的显式null是清空，须经该字段校验和确认。非nullable字段null拒绝。空字符串仅在原Schema允许时是值，不能自动替代null。空array对集合命令是显式空集合，是否允许由该命令决定。对象整体删除必须用生命周期命令，不能以null/空列表隐式删除。
- Aggregate legacy setter的“省略”可能不等于稀疏。本Beta公开更新只允许表内明确的稀疏字段合同，或完整授权Base上由既有Authority证明保真的legacy命令。Layer 1必须修复不保真的Port，不能让Layer 2补齐隐藏字段或把信息塞Notes。
- Core响应保持正式CoreReceipt及其FULL/STATUS_ONLY投影。Trip保持TripCreate/Metadata Receipt。Ledger保持原Ledger Mutation Response和operationReceipt。统一的OutcomeView仅供MCP结果表达，绝不新建统一Receipt Store。

```ts
// 协议类型，不是实现代码。每个Domain response仍使用Registry的原Schema。
type OutcomeView = {
  capabilityId: CapabilityId;
  tripId: UUID;
  target: { kind: 'TRIP'|'ITEM'|'EXPENSE'|'EXPENSE_LINK'|'CURRENCY'; id: UUID };
  operationId: string;
  outcome: 'APPLIED'|'NO_CHANGE'|'CONFLICT'|'REJECTED'|'UNKNOWN';
  receipt: CoreReceiptProjection | TripCreateResult | StructuredMetadataReceipt |
    ExpenseMutationResponse | ExpensePaymentRecordResult | ExpenseConflictResolutionResult | JourneyCurrencyCommit | TripLifecycleReceipt | null;
  revision: number | null; // 领域Revision，不把Core collection revision当Item revision
  errorCode: string | null;
  query: { capabilityId: CapabilityId; pathParams: Record<string,string>; query: Record<string,string> };
};
```

Core APPLIED/NO_CHANGE按正式Receipt。Trip metadata before=after时revision不增。Ledger `KEPT_SERVER`是用户保留服务器事实，`SUPERSEDED`是原命令被合法后继替代，两者必须原样报告，不伪装请求的编辑已APPLIED。UNKNOWN是客户端/边界未能确认正式结果，不是服务器写入后的虚假Receipt。查询缺失/不可见仍UNKNOWN，不能当NoCommit。

所有Mutation的可恢复状态必须能通过原Owning durable op/receipt读取。若现有Ledger ancillary接口仅有幂等写而缺可验证的原operation持久读取，Layer 1在既有Ledger owning journal上补读/原intent绑定；对ExpenseCreate/Update之外的Currency、valuation、Expense payment-record/conflict-resolution同样适用，不另建MCP journal。

方法名不决定副作用。Settlement preview必须零业务写；本候选Currency preview要求纯业务只读。Main现有Currency preview会写rate-demand/请求报价，Layer1需提供上述NEW_READER纯投影，先返回缺价/不就绪，不能偷带FX任务。明确FX lookup沿用既有缓存/报价来源，不调用OTR模型。Header、query严格schema，拒绝重复/未知query、跨origin cursor和任意URL跳转。业务页面返回private/no-store，原Receipt若当前不可见不泄漏正文。

### 权限策略名称

`TRIP_READ`当前合法成员/创建者；`TRIP_OWNER`正式creator/owner；`CORE_READ/CORE_MANAGE`继承coreCanRead/coreCanManage。后者要求可读且对象owner，或非PRIVATE、canManageShared且ITEM为WHOLE_GROUP。`CORE_CREATE`继承正式创建资格。不能把Organizer理解为可以改他人PRIVATE或非WHOLE_GROUP对象。

`LEDGER_EDIT`继承原Expense creator/Organizer、最终版本保护及修正权限。已纳入Final的Expense禁止普通Update/Delete/Restore，本Beta返回FINALIZED_SETTLEMENT_PROTECTED，提示只读查看原因；MCP不调用Settlement Correction替代。`LEDGER_ORGANIZER`沿用正式Currency权限/Final guard。`PERSONAL_PAYMENT_READ`仅本人/对端/正式允许Organizer读范围，不允许任选memberId冒充Self。People读取不获得Account connection或成员管理权。

Confirmation由Layer 3复用现有可信ConfirmChanges绑定Account/client/resource、原操作集合和准确Preview摘要。它不是新的Server业务权限。Layer 1测试调用者显式批准合成请求，Server仍独立执行ACL/CAS。Layer 2只能提出需要确认的步骤。Scope Consent不等于批准某次修改。

## 4. 可执行请求Schema与字段合同

Schema Alias是实际固定export，类型中 `?`表示省略，`|null`表示允许清空，未写默认值的字段没有隐式默认。Layer 2可用纯Schema源进行离线Validate，不调用Backend、Auth或数据库。TypeScript泛型表达的是可生成JSON的合同。

### 通用查询、响应和新增Port


### Roster与Item更新前的正式Reader投影（Layer1必交）

`otr.people.list`在现有Trip Person/ledger_members Authority上只读联接，必须以同一Trip、当前Actor可见的正式Person绑定和Ledger成员事实证实映射。当前A1模型可能使用相同UUID，但Layer2不得据此推导；只能使用响应明确给出的VERIFIED ledgerMemberId。payerMemberId、participants[].memberId、splits[].memberId均取此值；Item participation/visibility仍用personId。缺失/歧义/跨Trip映射阻塞对应Expense人员步骤，不影响无依赖的Item操作。不新增Member/Account管理、映射数据库或身份Authority。历史/非参与成员可否用于Expense仍由原Ledger命令校验，VERIFIED不等于允许写入。

基线依据：`docs/architecture/TRIP_CANONICAL_A1_I1_REPORT.md`、`src/data/api/ledgerReadContracts.ts::ledgerMemberSchema/ledgerBootstrapResponseSchema`。当前MCP roster Adapter只返回person_id，不能作为满足新映射合同的证据。

原`itemEditBaseOutput`只有DTO、ITEM record与read basis；DTO可丢description/category，单ITEM不包含独立RELATION记录。因此六类Get共享同一NEW_READER扩展，不另增六套Authority。新增普通HTTP ItemSnapshot如下，复用基线严格Schema，不允许任意JSON：

```ts
type ReadCoverage = 'COMPLETE_AUTHORIZED'|'REDACTED_OR_PARTIAL'|'UNAVAILABLE';
type ItemChildTable = 'itinerary_transport_endpoints'|'trip_endpoint_details'|'trip_flight_intents'|
 'itinerary_transport_services'|'trip_stay_details'|'trip_stay_rooms'|'trip_rental_details'|
 'trip_rental_places'|'trip_activity_details'|'trip_activity_entry_places'|'trip_transport_operational_facts';
// CoreRelationRecord = coreReadRecordSchema的kind='RELATION'判别分支，body.row严格按tableName校验。
type ItemSnapshot = BaseItemSnapshot & {
 actorAccountId:UUID;
 relations:{participation:CoreRelationRecord[];visibility:CoreRelationRecord[];expenseLinks:CoreRelationRecord[]};
 coverage:{root:ReadCoverage;children:Record<ItemChildTable,ReadCoverage>;
   relations:{participation:ReadCoverage;visibility:ReadCoverage;expenseLinks:ReadCoverage};
   fieldAvailability:{path:string;state:'READABLE'|'REDACTED'|'UNAVAILABLE'}[]};
};
```

relations严格限定本Trip、本Item的`trip_item_participants`、`trip_item_visibility_people`及`expense_links`（ITINERARY_EVENT target_id=itemId）。不得带其他对象/未授权Expense内容。完整ITEM root、11类child及所有合法field_state/source/protected/evidence标识保留；字段值仍按当前ACL脱敏，不扩Source Proof。空数组只有COMPLETE_AUTHORIZED才表示授权集合为空。coverage/fieldAvailability为Authority产生；未列出的路径不能推断可读。

DTO、record、relations、basis必须来自同一认证collection快照/epoch/access_revision，Item/Trip/family/semantic revision一致，所有关系revision与证书保留；不可拼接不同时间读结果。授权description/category从record做无损投影，发现不一致返回STALE_PREVIEW而非猜值。Layer2以raw record及field_state为保真基础，不能仅用展示DTO重建setter。

逐类必读：P1 root/temporal/Place/category/group/status；P2 intent、两个端点、Service、annotations及civil/source元组；P3 Stay/全部稳定Room集合；P4五标量和pickup/return完整地点；P5 Service/双端/annotations/三个operational角色；P6 Activity/Entry/Category；各类同时有参与/可见性/已授权Expense关系。Booking/Instruction/Document只读摘要不赋予写权。

稀疏修改只需其正式Owning Port要求的完整授权Base；部分脱敏不得自动清空，也不应阻塞无依赖的安全稀疏字段。若aggregate setter需不可见叶子，返回BLOCKED_CAPABILITY/INCOMPLETE_AUTHORIZED_BASE，等待保真Port；绝不让Layer2补隐藏值。Layer1需验证11 child覆盖、3关系组、错Trip/旧access revision/字段脱敏及source field_state保持。

### 生命周期合法Base Reader

`get_item_lifecycle_base` / otr.item.lifecycle.base 输入path tripId/itemId及query `{family:Family}`。`get_trip_lifecycle_base` / otr.trip.lifecycle.base 输入path tripId，无query。两者均为NEW_READER，必须由原Owning读取完整可管理闭合子图后计算graphHash，不能从redacted或任意剪裁图派生。跨权限子图无法合法执行则返回403/NOT_VISIBLE，不泄漏未授权IDs或计数。


Trip状态转换固定为ACTIVE+ARCHIVE→ARCHIVED、ARCHIVED+UNARCHIVE→ACTIVE，ACTIVE或ARCHIVED+DELETE→DELETED。已处目标状态且仍满足当前ACL/CAS的同义请求返回NO_CHANGE、不增metadataRevision；同一operation重放返回原不可变Receipt。实际状态变更只递增既有metadata aggregate版本。DELETED不能UNARCHIVE/RESTORE，返回REJECTED/INVALID_LIFECYCLE_TRANSITION；stale CAS返回CONFLICT，不从缺失Reader推断未提交。归档保留合法读取，普通业务写入拒绝TRIP_ARCHIVED，只有当前owner可Unarchive或明确Delete；恢复不复活被删Item/撤权成员，不修改Final财务。原ID查询复用同一Trip durable operation/receipt和actor绑定，不另建恢复引擎。

lifecycle Mutation必须绑定同一Base目标/revision/graphHash，执行时原Authority重查；该Reader不授予后续Mutation权限。后果已变化必须重新Preview和确认。

```ts

type AuthoredPlacePatch = Patch<Pick<Place,
 'authored_label'|'authored_text'|'authored_address'|'authored_address_line1'|'authored_address_line2'|
 'authored_address_locality'|'authored_address_region'|'authored_address_postal_code'|'authored_address_country'>>;

// 相关clock与precision成对校验，来源instant不允许此patch写入；现有Core求值/失效规则仍是Authority。
type SparseSchedulePatch = {start?:SparseBoundaryPatch;end?:SparseBoundaryPatch|null};
// payload={schedulePatch:SparseSchedulePatch}，至少一项非空变化。start不可整体null，end:null显式清除，P3不可清空checkout/end.local_date。
// 省略保持旧tuple/provenance；有变化按现有Temporal规则校clock/precision/zone并处理不再匹配的instant。
// legacy {schedule:CoreSchedule}继续读取，重写未改事实时拒绝，不能混用schedule与schedulePatch。
type SparseFlightPatch = {flightNumberLiteral?:string;origin?:{airportCode?:string|null;name?:string|null;terminal?:string|null;time?:SparseBoundaryPatch};destination?:{airportCode?:string|null;name?:string|null;terminal?:string|null;time?:SparseBoundaryPatch}};

// 上述都是现有setter的窄overload，保留legacy完整命令读取和原Receipt兼容，不新增通用Patch Engine。
type ItemParticipation = CoreEnvelope & {command:'SET_ITEM_PARTICIPATION';payload:{participation:Participation}};
type ItemVisibility = CoreEnvelope & {command:'SET_OBJECT_VISIBILITY';payload:{acl:Acl}};
type ItemHide = CoreEnvelope & {command:'HIDE_OBJECT';payload:{scope:'OBJECT_ONLY';affectedIds:{kind:'ITEM';id:UUID}[];graphHash:Hash}};
type ItemRestore = CoreEnvelope & {command:'RESTORE_OBJECT';payload:{scope:'OBJECT_ONLY';affectedIds:{kind:'ITEM';id:UUID}[];graphHash:Hash}};
type ItemDelete = Omit<CoreEnvelope,'command'|'payload'> & {command:'DELETE_ITEM';payload:{reason:string;graphHash:Hash}}; // OD02，合同新增Core lifecycle命令
// graphHash由正式授权lifecycle子图读取结果提供，不能对随意裁剪图自行hash。当基线Reader无法交付该hash，Layer1需补同Owning Reader投影，不能反复协商payload。
```

`ExpenseCreateCommand/UpdateCommand/DeleteCommand/RestoreCommand/ValuationCommand`均为`ExpenseCommand`的envelope.patchOrIntent.type分别CREATE/UPDATE/DELETE/RESTORE/APPLY_VALUATION判别子类型。返回**ledgerExpenseMutationResponseSchema**，不是Native本地`expenseOperationResultSchema`。后者仅用于客户端操作状态，不能假作HTTP成功回执。

Expense–Item Link/Unlink只允许本Beta的ITEM target，`LINK_EXPENSE`/`UNLINK_EXPENSE` 合同payload `{expenseId,targetKind:'ITEM',targetId,expectedExpenseRevision:positiveInt}`，target为稳定EXPENSE_LINK，baseVector含其原状态以及合法Item版本，expectedExpenseRevision来自真实Expense读取，由原Owning交易核对权限/当前ID/Revision。该窄扩展计NEW_OWNING_CHANGE，不在MCP新建关系Authority。两端当前读/管理权分别核验。link失败不撤销Expense成功，关系独立读回必须能确认。

Settlement仅提供Preview、List/Get/History、已有Payment状态、Personal Payments/Review读取和JSON数据Export。Preview直接采用已有`settlementPreviewRequestSchema/settlementPreviewSchema`，包含current inputs/balances/transfers、inputDigest、sourceAsOf/fingerprint、confirmedSettlement、confirmationDiff和blockers。它不Finalize、不写Checkpoint、不触发Settlement FX preflight状态修改。只读时看不到当前结果应返回明确未就绪/旧缓存信息。

Settlement Confirm/Adjustment/Correction/Reopen/Supersede/Payment Record/Confirm/Reject/Dispute/Correct，以及Personal Payment Create/Edit/Delete和Personal Review Checkpoint不在103个Registry ID中。Layer1可保留Native现有实现，但MCP权限映射/规划和Layer3Binding不得暴露这些写入。Expense修改可能改变未确认Current计算，这是原Ledger效果，旧Final inputs/版本保持不可变。

## 6. 独立Readback与Layer 1逐API完成定义

- Trip Create查看原TripCreateResult和Discovery同ID，再读metadataRevisioned snapshot；Update查看原metadataReceipt和新的metadataRevision，同义NO_CHANGE不增版本。Archive/Unarchive/Delete按OD01查lifecycle receipt及Discovery/metadata的正式状态。
- 六类Item经正式Core原operation FULL Receipt核hash/intent/targetVector，独立PG只读验证同Item、实际改动及未改字段，再由普通Item/collection Reader和iOS读回。关系用Core expense_links及其正式reader，不凭Item摘要缺link推断不存在。
- Expense用原command/status与Expense detail、LedgerBootstrap/changes验证同ID/Revision/participants/splits/valuation；Currency校settingsRevision/原changeId；valuation/payment-record/conflict-resolution查各自原Owning result与readback。派生Current Settlement变化可以读验证，禁止据此生成新的Final。
- Settlement所有接口必须以计数/审计确认业务数据库无写入、无Checkpoint、无支付确认、无Provider模型调用。JSONExport权限等同数据读取，不产生Storage对象/URL或新Auth权限。

每个Registry行的 `L1-{capabilityId}` 完成定义为合法actor正例、foreign/角色负例、Schema/null/省略、fresh CAS、精确重复/异intent冲突、响应丢失/UNKNOWN原ID恢复、独立PG及正式Reader一致。只读接口以snapshot/pagination/ACL和零业务写入替代Mutation测试。OD01–OD06已接受；真实实现/权限缺口仍明确BLOCKED，不用永远返回假成功交付API。

层级Server API PASS与Sync/UI PASS分别登记。HTTP→Core/既有Ledger Authority→PostgreSQL→Reader通过仍不足以满足Layer1总出口，必须继续Sync文档中的SQLite/UI/Cold Restore。

## 7. 版本、兼容与未决

不修改历史Core/Trip/Ledger op payload，新增稀疏overload保留旧parser/Receipt读取。新HTTP reader与新lifecycle命令为本候选，运行目录必须声明implemented/allowed，未知能力返回明确不支持。无版本号或额外字段不能被宽松接收。细化S/M/L、确切Owning/allowlist/Reader数量见Gap Matrix，Owner语义问题仅见Decision Register。

Layer3 OAuth/消费者传输复用现有标准Remote MCP，认证/撤销仍遵循现有Auth合同。此候选不新建OAuth业务Scope白名单，不使用固定QA账号/Client/窗口作为产品约束。

`ToolName<C>`取以上唯一toolName，`PathParams<C>`是path中的{placeholder}集合；`Query<C>`是GET对应requestSchema，非GET是Empty；`RegistryRequest<C>`在GET是Empty、非GET是requestSchema。Family工具必须与该Registry行family一致，不能把P3 payload交给otr.p2.create。Header及Idempotency不是LLM自由字段，由Layer3按正式command绑定生成。

`ItemLifecycleBase`补充必填 `state:'ACTIVE'|'HIDDEN'|'DELETED'`，与ItemSnapshot同ID但独立正式状态Reader。`ItemListQuery`补充 `includeDeleted?:boolean` 默认false，仅当当前有管理权才可true。Reader端状态与Core生命周期来自同一Authority，Layer1在现有Core mirror/read projection演进中消费该值，不建立MCP独立状态存储。Native按此正式观察更新现有Root/Day/lifecycle投影，数据库物理列/Migration编号由Layer1唯一Writer分配。

OrUnknown是Layer3语义。现有HTTP 404/403/503保留正式错误body，按原请求映射UNKNOWN/无权，不改为伪成功200。新增LedgerStatus的UNKNOWN requestDigest=null，不能回显caller摘要伪造原意图。

Currency纯预览使用新增`POST /v2/trips/{tripId}/ledger/journey-currency/preview-readonly`，复用原纯计算/读取Port，不claim rate demands。Main现有`/preview`原Native副作用和调用者保持原合同，不由本候选偷偷修改。Layer3只绑定Registry中的readonly预览。若缺报价，明确返回原Preview缺价/不就绪，不后台替用户产生新模型或费用。
