最新Owner范围覆盖原附件中的Settlement写入清单。MCP可新增/修改Expense，Settlement只读。保留原附件的Expense Delete/Restore范围与原Ledger权限，Settlement及其Payment/Personal Review写动作退出本Beta。Personal Payments按保守边界仅读，独立身份/付款声称仍遵循Ledger原模型。以上范围决定在本包统一应用。

## 1. 统计口径

API是method+模板path，Command dispatch是同一端点下一个明确command分支，业务能力按family和操作细分；字段叶子是Schema覆盖项。Counts不能互相相加为开发任务。批次只用已有逐项Adapter，不增加服务器级事务API。

本冻结合同有 **103个Stable Capability ID、42个method/path组合、64个API/Command dispatch单元**。其中已有正式Server接口/命令单元34，需要新增/改造Owning Port单元14，新增普通授权Reader投影单元16。三个类别互斥且合计64。新增Owning包括已有setter新增稀疏语义，不代表全部新建持久存储。

现有资格/allowlist需修复9个dispatch单元，与前述Port类别重叠。需要Layer3 MCP接线/修复的能力100个，共享Tool和同端点不重复计工程量。所有103个能力均需Layer2 Guide/Plan conformance，但不等于全部Guide从零重写。207条原审计对应见§4，明确范围外部分。

Sync有31个能力带新增/变化生命周期影响，但不是31个新Reader。最小已确定工作为 **2个新增lifecycle Reader消费、2个既有Reader消费修复、1个现有Trigger调度修复及正常产品接线；0个强制新增Trigger技术实现**。既有Version/Realtime不算已激活。OD04正式≤15秒：既有8/15/30/60秒自适应轮询不能直接满足，SY05必须修调度并为Reader/安装/渲染预留预算；不强制Realtime。

## 2. 互斥Server类别与重叠工作标记

`READY_EXISTING`只表示正式接口/命令合同与源码已有，不代表当前Server/Hosted/Simulator通过。`SERVER_GAP`包括NEW_OWNING、NEW_READER与资格修复，必须逐种标注。`SYNC_GAP`、`MCP_BINDING_GAP`、`GUIDE_GAP`是可重叠维度。OD01–OD06均ACCEPTED，不再标OWNER_DECISION_REQUIRED；真实接口/验收缺口仍保留，`POST_BETA`由最新Owner范围或明确排除决定。
