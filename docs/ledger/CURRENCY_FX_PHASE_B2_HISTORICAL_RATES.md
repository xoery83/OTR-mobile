# Currency / FX Phase B2 — historical daily candidate pipeline

Date: 2026-09-17. Scope: Dev historical quote acquisition and offline candidate cache only. Provider due diligence is in `CURRENCY_FX_PHASE_B2_PROVIDER_REVIEW.md`; ADR 0021 records the candidate/accepted-evidence boundary.

## Request and source

`HistoricalRateRequest = { economicDate, quoteCurrency, settlementCurrency, policyVersion }`. The first field is the explicit Expense date-only value from B1, never a transformation of `occurred_at`. The direction is **1 original/quote currency = `decimalRate` Journey settlement currency**. Policy `ECB_DAILY_V1` selects Frankfurter v2's pinned ECB route, not its blended default. Its returned `date` is the actual `referenceDate`; it may precede `economicDate` by 0–7 calendar days. An earlier day, future day, malformed/duplicate pair, unsupported currency, nonpositive or invalid decimal, or wrong direction cannot become a candidate. A future economic date and an unpublished current-day rate remain unresolved, never silently substituted with the latest rate. Provider numeric text is preserved without a JavaScript floating-point round trip.

## Demand and retries

Canonical cross-currency `RATE_REQUIRED` Expenses with non-null `economic_date` are the durable demand. A Backend process scans on start and every 30 seconds; SQL groups identical Journey/date/pair/policy needs, excludes a fresh cached quote and leases each due key once for 45 seconds. A process exit leaves the Expense demand and the lease expires. The scanner is independent of screen opens and Mobile uptime. Same-currency and unknown-date Expenses never create provider traffic. `ledger_rate_quote_attempts` stores only lease/retry metadata, not a second financial truth. `TEMPORARY_FAILURE` retries after 5 minutes, `RATE_LIMITED` after 15 minutes, `NOT_YET_AVAILABLE` after 1 hour, `NO_REFERENCE_WITHIN_POLICY` after 24 hours, and `UNSUPPORTED` after 7 days. None is permanently negative. Structured logs include request key, reference date, fallback days, failure class and next retry, but not Expense titles, tokens or notes.

## Cache, authorization and lifecycle

Dev migration `20260917000300` extends existing Journey-scoped `ledger_rate_quotes` with separate nullable `economic_date`, `reference_date`, `policy_version`, and `source_reference`; old quotes remain distinguishable and are not backfilled. Migration `20260917000400` adds a generated `decimal_rate_text` read projection so PostgREST/JavaScript cannot round the numeric candidate before Mobile receives it. One unique request key reuses a candidate for any number of matching Expenses. Positive candidates expire after 30 days and can be refreshed under the same key. Existing `effective_date` stays for older Stage 5 readers; B2 sets it to the **actual reference date**, and never treats it as both dates. `provider_reference` holds the exact Frankfurter request and `source_reference` the ECB attribution URL.

Existing authenticated Journey reads, bootstrap and change feed project only that Journey's quotes. Mobile SQLite v23 caches both dates/source metadata; repository reads require current-account actor context and Journey scope. The cache remains readable on offline cold start after acquisition and pull. No provider URL or secret is configured in Mobile code. `GET /v2/trips/:id/ledger/rate-quotes` retains its existing array contract; new optional fields are backward-compatible. No extra read architecture or global rate dump is introduced.

The quote is a **mutable candidate**, never accepted Expense valuation evidence. B2 does not enqueue `LEDGER_APPLY_VALUATION`, change `RATE_REQUIRED`, alter money/splits, or modify an accepted `ExchangeRateSnapshot`, Review result or finalized Settlement. Phase C must separately approve source usage and attribution, bind both dates to immutable evidence, validate Expense revision, and perform the existing Stage 5 acceptance path.
