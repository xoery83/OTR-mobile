# Phase B2 provider review — 2026-09-17

Decision: use Frankfurter v2's **pinned ECB provider route** for Dev-only, unaccepted historical quote candidates. Do not use Frankfurter's default blended feed. This is not approval to accept an ECB rate as settlement evidence in Phase C.

## Verified contract

- [Frankfurter v2 documentation](https://frankfurter.dev/) and [OpenAPI](https://api.frankfurter.dev/v2/openapi.json) expose historical `date`, provider-specific `/v2/providers/ecb/rate/{base}/{quote}`, actual `date`, `base`, `quote`, and numeric `rate`. The route may derive a cross-rate through the ECB's EUR pivot; OTR requests original currency → Journey settlement currency and does not invert responses itself. The public API needs no key. Its MIT software license does **not** license underlying ECB data.
- Live `GET /v2/providers/ecb/rate/EUR/NZD?date=2026-07-12` returned HTTP 200 `{date:"2026-07-10",base:"EUR",quote:"NZD",rate:1.9808}`: the Sunday request falls back to Friday and exposes that true reference date. A live pinned ECB query for 2026-07-15 returned all 11 requested target currencies: AUD, CHF, CNY, DKK, EUR, GBP, ISK, JPY, NOK, SEK, USD; NZD was the request base. This verifies coverage for NZD, AUD, USD, EUR, GBP, JPY, CNY, ISK, DKK, NOK, SEK, CHF on that historical day, not a guarantee for every date.
- Frankfurter v2 returns JSON numeric tokens of variable decimal precision. The adapter must preserve the raw decimal token and bound it to the existing exact decimal parser; parsing through a JavaScript `number` before persistence is not acceptable. It must reject direction/date mismatches, duplicate/malformed data, nonpositive values, future requests, and reference dates beyond seven calendar days. The API itself may return an older day without OTR's limit.
- [Frankfurter FAQ](https://frankfurter.dev/) allows commercial use, no monthly/daily quota, but anti-abuse rate limiting and no stated availability SLA. A [status page](https://frankfurter.instatus.com/) exists. Backend-only access, bounded timeouts, demand deduplication, cache and retry are required; failures cannot block Expense creation.
- [ECB reference-rate publication](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html) runs on working days except TARGET closing days and calls the rates informational, strongly discouraging transaction use. [ECB copyright conditions](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html) require accurate reproduction and ECB source citation, plus disclosure when data is modified; a cross-rate derived through EUR must be described as derived. The [ECB methodology](https://www.ecb.europa.eu/stats/pdf/exchange/Frameworkfortheeuroforeignexchangereferencerates.cs.pdf) names the required currencies. The provider reference must retain ECB and Frankfurter URLs for later attribution.
- Historical values can be corrected or revised. A cached quote is mutable candidate data, not an immutable accepted `ExchangeRateSnapshot`. Re-fetch policy must never rewrite accepted evidence. Phase C must explicitly decide whether ECB informational rates may be used for group settlement and how attribution/cross-rate derivation is shown to users; B2 does not decide this.

Provider replacement boundary: only the Backend adapter and policy version change. Stored candidates retain provider identity, reference date, request date and source reference; Mobile receives authorized Journey projections, never a provider URL in its bundle.
