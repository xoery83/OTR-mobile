# P4a read-only local Operations

Date: 2026-10-08 (Pacific/Auckland). Owner-authorized Builder; independent review pending.

The Owner accepted the P4 design for P4a only and authorized a DEV-only,
Account-scoped local projection. No C2/P2/P3/R3 integration or provider activation
follows from this decision.

Use the existing diagnostics surface and existing local source owners. SQLite50's
repository exposes finite operational metadata, not material/evidence, request pins
or private content. Cached Trip actor admission uses the existing offline Capture
predicate; an absent actor denies the entire continuation source without identities
or counts. This metadata read does not certify Import admission, retained result
access or provider availability. No execution repository is constructed with fake
admission callbacks.

A shared Account apply gate and read transaction bind the projection to a captured
Account generation. Readers use SELECT only. Older non-shadow UNKNOWN/install/meter
responsibility survives current-pass and queue completion. Sync error UNKNOWN is
separate from uncertain provider execution. Sources are explicitly available,
limited, denied or unavailable; intake, semantic Review and server are unavailable
in P4a. Detail is limited to 50 observations per local source, with a 51st row used
only to signal limited coverage; unresolved attempt flags cover all non-shadow
attempts for each observed task.

The view subscribes to Account generation and clears memory on blur/unmount;
late and superseded reads cannot publish. There is no database projection cache,
export, telemetry, automatic scan/repair, queue wake, provider recovery, timer or
new scheduler. User semantic attention is known only for existing sync conflict/
validation evidence; continuation semantic attention stays unknown. Existing Data
Health attention remains labeled recorded aggregate attention, not new Review.

Startup owns database initialization. Diagnostics can only read the already
initialized handle; a missing handle fails closed without opening/migrating it.
The Foundation display uses SELECT counts rather than side-effectful listPending,
and opening diagnostics no longer refreshes auth over the network. Explicit DEV
authentication actions retain their existing behavior.

Local attempt usage keeps nullable values and owning observation quality. Cost
is null/UNKNOWN because no billing source is composed. Age uses device-clock
observations only; server/caller-clock, unrecorded queue-clock, invalid and future values have unknown age.
No stale threshold, ETA, percentage, terminality proof or automatic-retry admission
is inferred. All new labels use canonical theme/controls and en/zh-Hans catalogs.

Historical migrations, canonical writers, sync policies, Account/Trip authority and
all remote runtime gates remain unchanged. Before extending beyond P4a, require
accepted C2/C3/P2/C4 handoffs and separately authorized P3/R3 sources and policy.

## Owner authorized F1–F6 correction boundary

The independent review identified inherited session adoption and preference-factory
initialization effects, incomplete older-attempt validation, retained scheduling
versus execution failure, Foundation publication races, and unsupported empty copy.
Diagnostics will read only adopted v2 sessions and initialized SQLite handles;
normal startup migration/adoption remains unchanged. Every non-shadow contributing
attempt's finite responsibility labels must validate. A current terminal failure
requires operator attention without certifying retry eligibility; older UNKNOWN
remains dominant. Foundation adopts the existing Operations focus/sequence cleanup
pattern. Empty copy requires a successful continuation or sync row-source read.
