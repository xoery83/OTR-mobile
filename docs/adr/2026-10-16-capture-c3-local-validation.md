# Capture C3 local validation continuation

Status: candidate for independent review. This decision does not open C4 interpretation, Source admission, Trip attribution, Backend, or provider execution.

An accepted C2 input can enqueue one `CAPTURE_PROCESSING_VALIDATE` operation in the existing `sync_operations` table. Its immutable payload pins the actual Batch manifest, input revision, Capture revision, payload identity, byte count, and SHA-256. The owning C3 repository verifies those pins and the retained original bytes under the Account gate. A completed operation means only `INPUT_VALIDATED`. A failed or interrupted operation retains its own queue responsibility; a successful input is never scheduled again. SQLite66 appends queue state changes to `capture_processing_events`, which Activity reads from the owning repository.

The dedicated worker has its own operation filter, Account-scoped claim owner, lease recovery, and compare-and-set settle. Successful settlement rechecks the current pin in its transaction. Claim checks the persisted retry deadline and attempt count. One Account-fenced foreground timer follows persisted retry and lease deadlines, stopping in background and on Account change. The generic sync engine always excludes this local operation. Normal startup is closed; a DEV-only explicit `captureProcessingDevConfig` overlay can select one accepted QA Batch for automatic scheduling on its normal Activity or reopen read. Production has no automatic scheduling path. C4 has no output profile, dispatch, or Review authority in this package; Activity remains waiting for an interpreter after local validation. Activity summarizes each Input's latest recorded state, with failure and retry taking priority.
