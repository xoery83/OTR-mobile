Future routes (not implemented/active in W0): `GET /v2/trips/:tripId/core/capabilities`, `POST /v2/trips/:tripId/core/commands`, `GET /v2/trips/:tripId/core/operations/:operationId`, `GET /v2/trips/:tripId/core/collection`, `GET /v2/trips/:tripId/core/objects/:kind/:id`, `POST /v2/trips/:tripId/core/documents/:id/open`. They use existing authenticated API/repository/queue layers. No feature direct Supabase/SQLite access.

Capability strict object: `{contractVersion:2,commandVersion:2,readVersion:2,captureVersion:2,activationState:CLOSED|ENABLED,enabledCommands:CommandEnum[],enabledFamilies:(P1..P6)[],enabledAdmissionModes:(MANUAL|REVIEWED_SOURCE|AUTO_SOURCE)[],maximumRequestBytes:32768,maximumAffectedRoots:32,maximumRelations:64,resolverAvailable:boolean,sourceEvidenceAvailable:boolean,operationalCustodyAvailable:boolean}`. Empty enabled lists and CLOSED are authoritative defaults. Individual capability absence blocks that command only; local valid intent save remains possible. Unknown version HTTP426; capabilities cannot self-enable database gate. Existing `/v1` discovery stays closed/unchanged.

Every command has EXACT keys `{contractVersion:2,intentVersion:2,operationId:UUID,tripId:UUID,command:CommandEnum,target:{kind:ITEM|BOOKING|ENTITLEMENT|DOCUMENT|INSTRUCTION|EXPENSE_LINK,id:UUID},baseVector:RevisionVector,admission:{mode:MANUAL|REVIEWED_SOURCE|AUTO_SOURCE,sourceIntentId:UUID|null,policyVersion:"otr.trip.auto-admit/1"|null},payload:CommandPayload}`. Actor comes from authenticated gateway, not request. RevisionVector is sorted unique array≤32 `{kind,id,revision:Revision|null}`; NULL only for intended new UUID, never wildcard. Existing references all included at observed revisions. Vector kind additionally SOURCE is permitted only for AUTHORIZE_DOCUMENT_COPY, binding source UUID/material revision through existing Source admission; proposed Document UUID has NULL base. No other command can mutate Source via this vector. Relation-only child ownership follows schema table. Command boundary rejects duplicate JSON keys, unknown keys, invalid Unicode/UUID/nonfinite values, request>32KiB, unused/missing base entries and arbitrary JSON paths. New-target ID is allocated once before durable queue insertion; deterministic slot mapping persists that UUID, not UUID-from-source-content.

MANUAL requires sourceIntentId/policyVersion NULL; owned finite user input sets protected bits. REVIEWED_SOURCE requires exact accepted reviewed source intent and user decision, policyVersion NULL. AUTO_SOURCE requires sourceIntentId and exact policyVersion, trusted bounded admission intent minted by Core policy, not provider/LLM/caller confidence. Both source modes bind authenticated Account/Trip, candidate, selected values, exact evidence and target vector. Credentials/visibility grants never auto-share. Flight evidence always TRACK_C/RETAINED finite grammar; manual literal alone cannot qualify.

## 3. Admission algorithm and transaction boundaries

1. Strict wire decode and authenticated Account/Trip fence; durable operation has frozen canonical text. Sort/validate lock vector; canonical request hash uses existing ECMAScript UTF-16-key sorted canonical JSON algorithm, domain prefix `otr-trip-core-intent-v2\n` plus exact text, UTF-8 SHA256.
2. Lookup exact actor operation key BEFORE fresh mutation gate. Same hash/Trip/command returns immutable previously recorded receipt; different use returns OPERATION_REUSE_MISMATCH. Replays still require current read authority; revoked actor gets redacted status/NOT_VISIBLE, never historic secrets. Known prior v1 operation-key collision cannot enter v2 fresh path.
3. Check enabled command/family/admission capabilities and actor object permissions; acquire deterministic sorted row/identity locks, final read set CAS. Auto must also pass candidate binding, proof coverage, ancestry, match policy and all field protection rules. Missing or partial target matches go Review; confidence cannot select the target.
4. Validate FINAL aggregate and sameTrip FKs, money/time/identity/access, graph closure for lifecycle and strict Flight proof rules. Never write first then validate. Existing unrelated rows cannot be affected outside vector; all root/relationship writes in supported single transaction commit together, increment affected parent revision once, update read-state and ACL generation once.
5. Write immutable terminal receipt in same transaction. Any rejected/conflict operation writes no business mutations, but gets terminal receipt with exact requested hash and safely redacted observed vector. No current hidden ID leaks. Server errors before terminal commit retry same immutable intent/key; never allocate a new UUID or key merely for timeout.

32 affected roots/64 edges maximum; larger import is dependent output slots, not giant transaction. Single CREATE_BOOKING with admitted existing Items links atomically. Source→new Items→new Booking→new Entitlement→Document/link outputs may cross independent aggregates: each has its own receipt and durable dependencies. Only dependency failures block later slots; accepted Item survives a later Booking error. No compensating deletion. A source workflow COMPLETE requires every intended output terminal or explicitly deferred/reviewed; `PARTIAL` means success count plus blocked/review slot IDs under source-owner authority, not global partial DB transaction.

Local write first: repository records durable intent + pending overlay + queue identity atomically, then returns `{localStatus:PENDING,itemId,operationId}`. This is not APPLIED. Offline original/plan readable under current Account; actor change pauses old account delivery. On reconnect deliver exact intent, install operation receipt, request actor-filtered v2 collection; overlay reconciles only if matching target/revision covered. CAS conflict keeps user draft and current accepted object separate; revised resolution is a NEW operation/explicit user decision; old receipt immutable. Queue owns retry/upload/sync, feature never does. Domain APPLIED but evidence finalization failed → EVIDENCE_PENDING: retry only lineage finalization using original domain receipt, not domain create.

## 4. Receipt and errors

Receipt exact object `{receiptVersion:2,commandVersion:2,intentVersion:2,actorAccountId,tripId,operationId,command,intentSha256,receiptSha256,targetVector:[{kind,id,baseRevision,committedRevision}],outcome:APPLIED|NO_CHANGE|CONFLICT|REJECTED,result:{created:TypedId[],changed:TypedId[],retiredEdges:TypedEdge[],replacement:TypedIdPair|null,custodyGrantId:UUID|null},errorCode:string|null,committedAt:Instant,audit:{before:FiniteSnapshot[],after:FiniteSnapshot[],evidenceRefs:string[],authorizationRefs:string[]}}`. Target vector may be redacted to requested target-only with inaccessible revisions NULL on status read; projection enum FULL|STATUS_ONLY and full receipt hash correlation must accompany response. Receipt hash is domain `otr-trip-core-receipt-v2\n` + canonical FULL receipt excluding receiptSha256; status projection does not assert hash-of-filtered-body. audit is immutable and hash-bound; FiniteSnapshot={kind,id,revision,facts} using only selected typed matrix facts. FULL receipt requires access to all represented roots and Source evidence; otherwise STATUS_ONLY carries correlation/outcome and requested target revision only, no audit or private related IDs. No raw original/QR bytes in audit. Before/after/proofs stay under root/Source ACL, not public result. Immutable business terminal outcomes200/201/403/409/422; transient5xx/429 have no fabricated terminal receipt.

## Exact DTO aliases and defaults

TypedId={kind:ITEM|BOOKING|ENTITLEMENT|DOCUMENT|INSTRUCTION|EXPENSE_LINK,id:UUID}; TypedIdPair={old:TypedId,new:TypedId}; TypedEdge={relation:one of six frozen N:M table names,parent:TypedId,child:TypedId}; graphHash is SHA256 of canonical sorted FULL authorized lifecycle relationship closure+root revisions under domain `otr-trip-core-lifecycle-graph-v2` and newline, minted by repository/reader with a finite graph scope. Incomplete/unauthorized closure cannot mint a WHOLE_BOOKING graph token. FiniteAddress is exact entity/field address in matrix including concrete role/service/room ID where applicable; no unrestricted path parser. ProofMap is NULL or finite address→string≤512, max64 for Flight, max256 elsewhere. required metadata/owner/revision fields never appear in input Fields objects. New Item status planned, hidden_at NULL, order_index/trip_day_id NULL; new Entitlement ACTIVE; price/due/optional details NULL when absent. CREATE_ITEM participation/acl required in wire after repository resolves authenticated role defaults. Family details optional on manual incomplete save except P3 start/end, P5 endpoints/service and sparse Flight literal/date. No mandatory property name/category/plate/provider or Room row. SET_* detail updates are finite partial business-field maps (≥1 field); rooms/places/operational sets selected separately. Omitted group retains; selected nullable member NULL clears with protected state, selected rooms list replaces room set with evidence/CAS, empty list is explicit user removal. Qualified Flight commands remain exact existing strict grammar regardless of these generic default rules.
