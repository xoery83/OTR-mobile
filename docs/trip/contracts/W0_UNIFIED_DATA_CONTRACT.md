## 1. Accepted authority and identity

- Item UUID is existing `itinerary_events.id`. No new parallel Trip Item root, global Flight Instance, compulsory Group or Other renderer.
- Root START/END own P1/P3/P4/P6 schedule. Exactly two Event-owned ORIGIN/DESTINATION endpoints own qualified P2 and P5 schedule. Root schedule/place is NULL for TRANSPORT; endpoint facts are never copied into independently writable root dates. Sparse P2 uses root CALENDAR until one guarded conversion.
- Typed detail rows own only extra service facts. P3 permitted check-in hours are not the user's planned arrival; P5 meeting/check-in/cutoff are finite operational prerequisites, not segment departure. P4 pickup/return places use role rows, root location is NULL; P6 root place is venue and ENTRY role is a distinct entrance.
- Booking is existing Reservation UUID, commercial contract/observations only. Reservation starts_at/ends_at/location legacy columns are read-only for v1 and NULL on v2; source-observed dates remain immutable observations. No accepted schedule can be changed through Booking.
- Entitlement is independently identified right, Ticket/Pass/boarding pass. Document is independently authorized immutable original. Wallet is presentation, not another entitlement database. Instructions are append/correct entries. Booking may also link independent Documents under its own N:M edge and Document ACL. Ledger alone owns payments, splits and expenses; commercial price/due never implies paid.
- Stable Account is authenticated identity; Person is existing journey_member UUID within a Trip. They are not interchangeable. Owner-account authorization is independent of optional Person binding. No name/holder alias automatically becomes access authority.

No silent Item schedule rewrite. Flight rebooking may preserve Item UUID through REPLACE_FLIGHT_SERVICE with revision/evidence protection; prior qualified service is retained in immutable receipt, not another current service row.

Lifecycle scope is explicit ITEM_ONLY, EXCLUSIVE_ARRANGEMENT or WHOLE_BOOKING with enumerated affected objects/revisions. Exclusive means exactly one active Item↔Booking and no other active entitlement relationship relying on that Booking. If graph changed, fail CAS; never broaden action. ITEM_ONLY cancellation keeps shared Booking ACTIVE. Whole-booking cancellation requires authority for every affected shared object and marks chosen linked Items canceled; private/unauthorized objects cannot be silently changed or disclosed. A missing authority yields SCOPE_NOT_AUTHORIZED without identifiers. Hide sole mistaken Item may hide exclusive Booking only under explicit scope. Documents and Ledger never cascade from Item/Booking hide, cancel, replace, unlink or eventual purge. Physical purge is out of Beta scope.

## 3. Exact value and temporal rules

UUID: lowercase canonical RFC UUID; client-generated non-content ID. Revision: integer 1..2^53−1; Int32 signed. PositiveInt 1..2^31−1; NonnegativeInt 0..2^31−1. SafeInt ±(2^53−1). Text(N): Unicode scalar count ≤N, valid UTF-8, no NUL or lone surrogate; required text trims nonempty. Date: real Gregorian YYYY-MM-DD, year0001..9999. Clock: HH:mm with precision−1, HH:mm:ss with0, or seconds plus1..6 fractional digits matching precision. Instant: exact UTC RFC3339 seconds plus0..6 digits; retain microseconds as string, never JS Date roundtrip. Offset ±64800 integer seconds. Latitude/Longitude finite ±90/±180, both NULL or both non-null. SHA256 lowercase64hex. Currency/Scale use existing Ledger compiled registry; Money tuple minor/currency/scale all present or all NULL, scale0..6 and exact currency scale; no float allocation. HTTPSURL(2048): https only, no userinfo, bearer query or secret fragment. ServiceKey ASCII `[A-Za-z0-9._:-]{1,32}`. MediaType allowlist application/pdf,image/jpeg,image/png,image/heic,image/heif,image/webp,text/plain,application/vnd.apple.pkpass only after bounded integrity/format verification; unsupported bytes remain Capture evidence, not claimed usable document. The existing Source-v1 format allowlist remains authoritative for PRIVATE_SOURCE_REFERENCE; a declared MIME alone cannot bypass it. WebP/pkpass require an explicitly negotiated compatible custody/input capability; without it remain private Capture bytes/observation and CUSTODY_UNAVAILABLE. Apple Wallet class can be recorded without pretending an original pass was admitted or installed. No v1 Source validator is widened by W0. Region = `{page:integer>=0,x:number,y:number,width:number,height:number}`, normalized finite0..1, positive extents, x+width/y+height≤1; actual page bound verified.

`FieldStateMap` is a JSON object keyed ONLY by finite matrix logical addresses, max256 entries/32KiB: each value exactly `{state:KNOWN|UNKNOWN|CLEARED, origin:MANUAL|SOURCE|PROVIDER|DERIVED, protected:boolean, changed_revision:Revision, evidence_ref:string<=512|null}`. No values copied here. Manual SET and CLEAR set protected=true; source/provided automatic writes cannot overwrite protected fields even if equal confidence. Unknown means no accepted fact, not explicit deletion; source NOT_APPLICABLE is observation and does not erase. Explicit clear is allowed only on nullable field, requires authorized user command or exact reviewed clear evidence. Required title/date and current qualified Flight service minimum cannot clear. Receipt captures before/after accepted values under object ACL; raw private evidence is never in Experience DTO. FieldState missing for legacy fields means protection unknown: auto mutation denied pending reviewed baseline, not inferred unprotected.

For root/endpoint/operational temporal tuples: date-only has local_date, DERIVED_CIVIL, UNKNOWN quality, PENDING resolution; clock/precision/source/instant NULL. Unknown boundary may retain date/zone but no invented clock/instant. Authored local clock without resolvable zone is retained with precision, ESTIMATED/DERIVED_CIVIL/PENDING, normalized instant NULL, and remains nonComparable. This v2 manual mode is validated by a new business-v2 dispatcher, never relaxed in v1 functions. Qualified civil tuple requires resolver-issued immutable interpretation_key/input hash, exact date/time/zone/offset consistency and UNIQUE or explicit FOLD_RESOLVED; GAP fails, unresolved FOLD enters Review. SOURCE_INSTANT requires exact supplied instant/precision and evidence; supplied civil labels must agree if resolver qualification is present. An offset added to an authored clock is not SOURCE_INSTANT proof. Final comparable end cannot precede start; different local dates/zones may legitimately differ. Unknown end/duration remain unknown.

P2 QUALIFY_FLIGHT keeps the CP13A Option-A grammar exactly: origin date required; origin EXACT + SOURCE_INSTANT and non-null source instant; destination UNKNOWN allowed; complete civil tuple date+clock+zone is rejected unless a separately reviewed future Flight resolver contract exists. Every selected finite leaf has exact TRACK_C/RETAINED coverage, no invented proof; codeshare graph/ancestry validation retained. W0 does not authorize that future Flight resolver or weaker admission. Civil labels can therefore remain incomplete even on qualified Flight; Day uses proven origin date and normalized instant with known precision.

## 4. Access contract

Read predicate: active authenticated Account/Trip membership AND (owner account OR visibility GROUP under existing Trip read permissions OR SELECTED_PERSONS grant through a server-verified current Account↔Person binding). PRIVATE has owner only. Existing Trip organizer permissions permit managing shared group plans, not reading PRIVATE objects or private originals. Selected participation does not automatically grant viewing; viewing does not imply participation. Defaults: organizer shared plan WHOLE_GROUP/GROUP; ordinary member SELF/PRIVATE. Organizer may also explicitly create SELF/PRIVATE. Booking/Entitlement/Document/Instruction created from Source default PRIVATE; explicit sharing is separate reviewed/user-authorized decision. Non-sensitive commercial summary can be made GROUP; PNR/holder/reference is not silently removed from a shared mixed object—creator must explicitly share that whole object or retain PRIVATE. Admission refuses auto GROUP for sensitive fields.

SELECTED_MEMBERS requires nonempty same-Trip Persons; inactive participants retained historically but not automatically reassigned. WHOLE_GROUP projects current participating roster and records roster fingerprint in read certificate; historical attendance is not inferred. SELF may have self_person_id NULL when owner has no current verified mapping; owner-private local creation still succeeds. Selected visibility cannot bind through display name or device cache speculation. Each protected read, open-original, link and lifecycle command reevaluates capabilities. Association DTOs return authorized objects only, never hidden ID/count/exists markers. Instruction requires parent and own ACL. A Source link does not grant Source access; GROUP Document with private original reference cannot advertise group-ready bytes. Explicit authorized-copy custody is necessary for independent shared original access.

Revocation and account switching fence all pending intents, certificates, caches and open capabilities; known revoked objects become inaccessible locally and cache keys are evicted/locked. Unknown offline server revocation cannot be instantaneously known: preserve existing valid-local-session/offline trust rule and pause sync on network/refresh failures. Never claim immediate remote deletion on disconnected devices. No extra arbitrary offline TTL or forced online launch introduced by W0.
