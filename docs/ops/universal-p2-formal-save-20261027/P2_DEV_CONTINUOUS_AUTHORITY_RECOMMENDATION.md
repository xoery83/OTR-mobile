# Minimal continuous DEV authority recommendation

Proposal only; no persistent authority installed. The present exact-ID P1/P3/P2 finite scopes prove individual slices, not a general P1–P6 issuer.

| Capability | Treatment |
| --- | --- |
| Normal QA Results, accepted Core reads, Day Feed and same-ID receipt replay | Existing authenticated Backend/Reader. No new Gate per read/test. |
| Ordinary default-closed Backend fixes/deploy/rollback | Existing Standing Deployment Authorization. |
| First P2 Sparse Save | One prepared qualified-execution window; same retained Candidate/Item/operation. |
| Later new reviewed P1/P3 or Sparse P2 candidates | One explicit persistent QA business-authority approval, rather than per-Batch temporary grants. |
| P2 Qualified/Journey/Booking/Ticket and P4–P6 | Remain closed until each type has its own qualified contract and acceptance. |

Reuse trip_sustained_dev_policy and current Backend Source Review→Plan→Admission→Core roles/RLS. A future precise package should replace exact golden-candidate pins in the existing sustained Source guards with a normal owning predicate: exact approved QA Actor/Trip, independently bound retained Source/Task/result, explicit original/Trip/NEW review, evidence-qualified family payload, immutable operation/target/Plan and receipt. No direct Candidate→Core, generic Confirm authority, new permission platform, role membership or broad table grant.

Initially allow only accepted P1, P3 and P2 SPARSE command grammar for this synthetic QA Actor/Trip, with an explicit project expiry and kill switch. Keep the existing Provider scope/budget independent. Airport identity resolution must use admitted registry evidence; the current AKL/CHC single-date rows do not authorize arbitrary airports/dates or Qualified Flight. Do not enable P4–P6 on the strength of candidate previews.

Expected protected changes for that future package: current sustained capabilities/Source guard/publication/historical-association/read-state guard definitions and the existing policy JSON; retain OID/owner/ACL/RLS and Account/Trip isolation. Exact generic predicates and hashes must be prepared and reviewed before approval. Persistent new-Create authority is not covered by a software image approval.

First remove any unnecessary dependence of already-accepted, receipt-bound Source finalization on a temporary Create flag, using the existing finalizer/Reader and immutable accepted receipt. That recovery must grant no new publication, Plan or Core Create. Prove default-closed recovery before claiming it.

Material risk: a persistent QA issuer authorizes additional correctly reviewed Items within that Trip; a predicate bug could admit an invalid Item. Limit families/Actor/Trip/expiry, retain uniqueness and independent rejection tests, make the kill switch observable, and avoid temporary administrator roles entirely. This recommendation requests no change now and does not delay the first P2 Save.
