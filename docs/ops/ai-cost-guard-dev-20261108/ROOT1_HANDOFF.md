# DEV AI cost guard for Universal Analyze

The normal Universal Capture Backend reads `AI_COST_GUARD_ENABLED` from its process environment. Only the exact value `false` on the fixed OTR Development project enables OFF. An absent, invalid or true value keeps the current guard, as does a non-DEV target. Configure the process running `server-capture.mjs`. The continuous and finite loaders and the Universal Provider use the same setting. The HTTP contract has no cost switch.

OFF retains normal signed-in Actor, Source/Trip permission, Provider configuration, remote transport and secret checks, and the same durable Task/Attempt/call and result pipeline. It uses the existing unpriced Universal START/dispatch route and records actual reported token usage in the existing usage table with unknown cost. It writes no monetary hold. The Provider logs that internal budget control is OFF and actual Provider charges may apply. Restore `true` to resume monetary enforcement. Prior requests and attempts retain their original identity and recovery path.

The source candidate requires the seven existing function-body changes in `backend/sql/universal_ai_cost_guard_candidate.sql` on DEV. The SQL keeps existing function identity, owners and ACL and checks each expected fragment exactly once in one transaction. Before protected installation, Root2 should compare the exact live definitions and preserve their full preimages using its existing DEV installer. Prepare uses the existing selection DTO. With OFF its price schedule ID may be null. The registered configuration, lifetime and budget snapshot shape stay compatible with existing Tasks. The snapshot value does not reserve or cap money in OFF. Provider request hash and finite Source/Provider identity still use the normal owning proof. No CP14 price append or CONFIG_ADMIN action is part of Analyze.

The finite DEV scope uses the additive `backend/sql/universal_ai_cost_guard_finite_nullable_candidate.sql` before inserting an OFF scope. Set the real scope's `price_schedule_id` to SQL NULL. The existing price foreign key and all other scope fields remain in force. With ON, the actual owning reserve function denies a null price. Restore the finite scope constraint with `backend/sql/universal_ai_cost_guard_finite_nullable_inverse.sql` after the owning scope is closed. The inverse rejects any active retained null scope row and preserves the historical Call, Task and Usage records.

The same `server-capture.mjs` entry also has an independently configured Flight Enrichment loader. Its extraction/search stack and the older one-shot Flight QA transport have separate price-linked SQL. This candidate covers the active Universal Analyze pipeline and does not claim global functional coverage of those separate paths.

Validation used the existing network-isolated PostgreSQL fixtures in both ON and OFF. OFF exercised sustained and finite scopes, protected START/mark, replay, no monetary hold and terminal usage readback. ON exercised the protected priced hold and admitted price. The TypeScript tests use the real Provider adapter with fixture transport, including OFF token reporting and no-send when custody denies. Hosted DEV and paid calls remain for the owning Lane.
