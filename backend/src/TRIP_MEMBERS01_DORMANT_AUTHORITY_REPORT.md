# WP-MEMBERS-01 dormant targeted Invite/Claim authority

Owner's direct 2026-10-14 finite-default approval supersedes the older A1-D §I/§K **PROPOSED** marker only for this bounded policy: an Organizer authorizes an exact target, a recipient explicitly accepts, a Person may exist before an Account, registered invitations restrict the exact Account, and an unregistered Person claim requires current exact identity confirmation plus exact-Account Organizer approval. Link does not create an Organizer role, edit right, PRIVATE access or a new Person; expiry, revoke and replay cannot newly admit or restore a revoked grant. Invite revoke is separate from existing membership. Historical financial and Person identity references stay intact. BD34's Account≠Person and visibility≠participation remain unchanged.

This packet adds one dormant Backend service and focused tests. `ISSUE_TARGETED_INVITE` targets either an exact registered Account or an existing unregistered Trip Person. `CLAIM_PERSON` requires an authenticated Account and explicit consent; the server authority must confirm the exact Person/Account pairing, current Organizer approval, live invitation, no prior denial and no competing Person link. `REVOKE_UNCLAIMED_INVITE` only revokes a pending unclaimed invitation. Exact operation replay returns a historical receipt with separately read current effective access and performs no second mutation. A changed command under the same operation ID is a conflict. The typed transaction offers only invite issuance, Person linking, unclaimed-invite revocation and receipt persistence; it cannot change grants, role, PRIVATE rights, finance or participation.

`MemberClaimAuthorityPort.atomic` is a mandatory injected server-serialized transaction covering all current Person/link/invite/Organizer/grant/identity/receipt reads and the conditional write. A provider must derive those facts from owning authority, not `canReadTrip`, email/name similarity or client claims. It must roll back the entire transaction if an operation or receipt write fails. No port is installed, so the default result is `UNAVAILABLE`; this packet adds no HTTP route, PG migration, Account provision, Auth change, Mobile UI, runtime activation or deployment. Exact SQL, DTO transport and provider installation are subsequent ordinary engineering work under the same approved behavior, with protected deployment still separately gated.

Author verification: eight focused tests PASS, TypeScript, UI guard, scoped ESLint, Prettier and `git diff --check` PASS. The tests cover closed default, unregistered-before-Account claim, exact registered Account restriction, Organizer versus read-only authority, identity/approval/consent, expiry/revoke/denial/conflict, malformed target, historical replay/current denial and unclaimed-invite-only revoke.
